# 메뉴를 먼저 고르는 배프

기존 setup.sql → menu-discovery.sql → distance-matching.sql 순서로 실행합니다. 기존 계정과 모집글은 유지합니다.

## 연결되는 기능

- 커피·햄버거·샌드위치와 가능한 가게 선택
- 오늘/내일의 한 시간 단위 수령 시간, 정문/후문/궁동 수령 지역 선택
- 계정당 주문 의향 한 개 저장·수정·취소 (여러 메뉴/가게 포함 가능)
- 공통 가게·겹치는 시간·출발점 간 직선거리 800m 이내인 사람 집계 (수령 지역은 달라도 됨)
- 모집글 없이도 양쪽 사용자에게 메뉴 일치 알림 저장
- 모집을 열면 조건이 맞는 사용자에게 참가 초대 알림 저장
- 메뉴·수량 선택 후 직접 모집 또는 기존 모집에 신청
- 서버에서 메뉴 가격을 확인해 주문 내역 저장, 수락된 참여자끼리 공유

## 매칭 조건과 표시

수령 지역 이름은 희망 장소를 표시하는 용도이며 매칭을 제한하지 않습니다.
각자 이동 한도 400m인 두 사람의 중간 지점을 찾을 수 있도록, 출발점 간 직선거리 800m 이하를 후보 조건으로 사용합니다.
현재 위치 또는 지도에서 직접 지정한 좌표를 사용합니다. 좌표가 없는 기존 관심은 재저장해야 매칭됩니다.
좌표는 본인만 읽을 수 있는 gd_intents에 보관하고 다른 사람의 화면·알림·모집글 본문에 노출하지 않습니다.
실제 도보 경로, 장애물과 사유지, 3명 이상이 동시에 만날 공통 수령점은 이 거리 조건만으로 보장되지 않습니다.
현재는 두 사람씩 매칭 후보를 찾는 단계이며 최종 장소는 채팅에서 합의합니다.
모집 인원은 가게 메뉴 화면의 ‘새 모집으로 시작하기’에서 리더 포함 2~5명으로 설정합니다.
관심 표시는 참가 확정이 아니며, 신청과 리더 수락은 기존 공동배달 규칙을 따릅니다.
이미 신청/참여 중인 계정은 새 관심 등록과 다른 주문 참여가 제한됩니다.
유효 시간이 끝난 관심과 알림은 조회에서 제외됩니다.
알림은 앱을 열거나 재접속할 때 확인할 수 있고, 운영체제 푸시는 포함하지 않습니다.

## 금액과 자료

카탈로그 메뉴는 기존 campus.ts의 공개 자료를 바탕으로 구성됩니다.
메뉴/가격 변경 시 gd_menu_catalog와 campus.ts를 함께 갱신해야 합니다.
가게의 실제 최소주문금액과 배달 가능 여부를 보증하지 않으므로,
UI에는 모집자가 확인·수정할 수 있는 '목표 주문금액'으로 표시합니다.
주문·입금이 자동 처리되었다는 상태를 생성하지 않습니다.

## 검사

로컬 PostgreSQL(PGlite)에서 시간/거리/가게별 매칭과 800m 경계값, 지역이 다른 근거리 매칭, 알림 중복 방지/취소,
사용자별 접근 권한, 서버 가격 계산, 초대 권한을 검사했습니다.
인증된 실제 두 계정에서 알림과 메뉴 공유가 함께 동작하는 확인은 별도 필요합니다.
