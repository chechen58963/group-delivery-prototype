# 사용자 테스트 피드백 반영

## 반영 내용

- 출발 위치의 GPS/지도 선택 상태, 지도 표시, 마지막 GPS 확인 시각과 정확도.
- 목표 주문금액 직접 입력과 −1,000 / +1,000 / +10,000원 버튼.
- 배달비 직접 입력과 −500 / +500 / +1,000원 버튼.
- 진행 중인 주문은 `screen=order`에서 현재 단계에 맞춰 이어짐. 메뉴 → 송금 → 배달 → 수령 → 완료. 채팅은 따로 열 수 있고, 기존 링크도 유지.
- 미완료 준비 항목에 맞는 다음 행동과 해당 설정으로 이동하는 버튼.
- 수락·입금 확인·수령 제안 등 읽지 않은 주문 알림을 화면에 유지. 읽음 처리하거나 내용을 확인하면 사라짐.
- 비대면 수령 제안과 전원 동의. 장소·시간·참가자가 바뀌면 재동의. 확정 이후 방식 변경 금지.
- 리더가 음식 도착 후 사진을 등록해 음식 놓기를 알림. 사진 등록과 각자의 수령 완료는 별도이며, 음식 놓기 전 수령 완료는 서버에서도 차단.
- 사진은 최대 10MB 입력을 JPEG로 줄여 저장하며, 사진 데이터는 상태 조회와 분리. 모임 참가자만 조회 가능.
- 이미 저장한 이동거리는 현재 GPS 갱신만으로 덮어쓰지 않음.

## DB 적용

`APPLY-MENU-IMPROVEMENTS.sql`까지 적용된 프로젝트에서 `APPLY-TESTER-FEEDBACK.sql` 전체 실행.
마지막 결과: **사용자 피드백 업데이트 적용 완료**.
기존 주문의 수령 방식은 직접 만나기로 유지되며, 재실행해도 주문·메뉴·정산·포인트가 초기화되지 않음.

## 가입 메일 발송 설정 — 별도 작업 필요

앱 오류 안내 수정으로 Supabase의 메일 발송 한도가 늘어나지는 않음.
2026-11-16 확인한 공식 문서상 기본 발송은 시간당 2통이며, 프로젝트 조직의 팀에 속한 주소로 대상이 제한됨.
팀원들에게 프로젝트 관리자 권한을 주는 방법으로 이 제한을 해결하지 말 것.

1. 사용할 메일 발송 서비스에서 SMTP 연결 정보와 발신 주소를 준비.
2. Supabase → Authentication의 이메일 설정 → SMTP 설정에서 외부 SMTP 활성화.
3. 서비스가 제공한 서버 주소(Host), 포트(Port), 사용자 이름(Username), 비밀번호(Password), 발신 이메일과 발신자 이름(배프)을 입력.
4. 발신 주소/도메인의 인증을 해당 메일 서비스에서 완료. 비밀번호와 API 키는 저장소·앱 화면·채팅에 넣지 말고 설정 화면에 직접 입력.
5. Authentication → Rate Limits에서 이메일 발송 한도를 메일 서비스의 허용 범위에 맞게 확인.
6. URL Configuration의 Site URL은 `https://group-delivery-prototype.vercel.app/`로 확인하고 배포 주소를 Redirect URLs에 등록.
7. 새로운 테스트 이메일 하나로 가입 → 인증 메일 수신 → 인증 링크 → 배프 로그인 → 프로필 생성까지 확인. 실패하면 Authentication 로그의 오류 코드를 확인.

오류별 의미:
- `over_email_send_rate_limit`: 프로젝트 이메일 발송 한도. 기다리기 안내만으로 해결됐다고 판단하지 않음.
- `over_request_rate_limit`: 인증 요청 횟수 제한.
- `email_address_not_authorized` / `email_address_not_allowed`: 메일 발송 대상 설정 확인.

공식 문서: https://supabase.com/docs/guides/auth/auth-smtp
발송 제한: https://supabase.com/docs/guides/auth/rate-limits
