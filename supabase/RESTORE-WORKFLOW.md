# 배프 공동배달 과정 복원

## 현재 프로젝트에 적용

현재 DB에 `setup.sql`과 `menu-discovery.sql`이 적용되어 있다면,
Supabase의 SQL Editor에서 `APPLY-UPDATES.sql` 전체를 새 쿼리로 실행합니다.
이 파일은 `distance-matching.sql`, `signup-profiles.sql`, `restore-workflow.sql`, `walking-rewards.sql`을 순서대로 묶은 파일입니다.
기존 사용자와 모집글을 삭제하지 않습니다. 실행 후 앱을 새로고침합니다.
실제 DB 실행 및 두 실제 계정의 브라우저 검증은 별도이며, 코드 작성만으로 적용되지는 않습니다.

새 DB에서는 `setup.sql` → `menu-discovery.sql` → `APPLY-UPDATES.sql` 순서로 실행합니다.
확장 후 예전 `setup.sql`이나 `menu-discovery.sql`만 다시 실행하면 확장한 함수가 덮어써질 수 있으므로,
재설치 시에는 반드시 이 순서 전체를 따릅니다.

## 연결된 흐름

메뉴로 배프 찾기 또는 검색·지도 탐색 → 모집 → 참가 신청·수락 → 각자 메뉴 저장
→ 모집 마감 → 리더 계좌와 수령 장소·시간 저장 → 리더 최종 확정
→ 각자 송금 표시 → 리더 입금 확인 및 자신의 결제 준비 확인
→ 리더가 외부 배달앱 주문 완료를 기록 → 배달 중 → 도착
→ 각자 본인 음식 수령 확인 → 전원 확인 시 자동 종료 → 상대 별점·후기.

- 가입 이용 권한은 이메일 인증 후 자동 활성화됩니다. 모임의 참가 신청·수락은 별개입니다.
- 현재 돈을 이체하거나 배달앱에 주문하는 API를 연결하지 않습니다. 계좌와 진행 상황은 사용자가 입력·확인합니다.
- 은행/계좌/예금주는 주문 참여자만 조회합니다. 인증된 외부인은 조회할 수 없습니다.
- 참가자 위치는 각자가 명시적으로 공유한 경우에만 모임 지도에 나옵니다. 공유 해제와 거래 완료 시 지웁니다.
- 모집 지도에는 모집자가 공개 수령점으로 지정한 좌표만 표시합니다. 개인 출발점은 공개하지 않습니다.
- 메뉴 매칭은 서로 다른 희망 수령 지역도 허용하고, 두 출발점 간 직선거리 800m 이내인지 검사합니다.
- 중간 지점 추천은 공유 좌표를 사용한 후보이며 도보 경로·출입 가능 여부를 검증하지 않습니다.
- 검색어·카테고리·목록/지도 선택·목록 스크롤은 화면을 다녀와도 유지합니다.

## 취소와 환불

- 주문 전 리더 취소 시 모임이 종료되고 참가자의 송금/입금 기록은 환불 확인에 남습니다.
- 참가자가 주문 전에 나가면 본인 환불 기록을 남기고, 남은 사람들의 메뉴와 분담액을 다시 확정합니다.
- 기존 입금은 지우지 않으며 추가 송금/초과 환불을 계산합니다.
- 리더의 환불 보냄 표시 후 해당 참가자가 수령을 확인해야 환불이 종료됩니다.
- 확인할 환불이 남거나 필요한 입금 확인이 안 되면 주문 완료를 기록할 수 없습니다.
- 주문 완료 이후에는 일반 취소/탈퇴가 금지됩니다. 예외 분쟁은 신고로 접수합니다.

## 평판·신고·혜택

- 실제로 완료된 모임의 상대만, 상대별로 한 번 평가할 수 있습니다. 자기 평가는 금지됩니다.
- 신고 내역은 신고자와 당사자만 읽을 수 있습니다. 일반 사용자는 타인을 정지할 권한이 없습니다.
- 운영자는 DB에서 `gd_resolve_report(report_uuid, confirmed, note, days)`로 검토 결과를 기록합니다.
  이 함수는 브라우저의 anon/authenticated 역할에서 실행할 수 없습니다.
- 리더는 약속 시간과 배달 도착 중 늦은 시점에서 10분 후부터 수령 지각 확인을 요청할 수 있습니다.
- 해당 참가자가 직접 지각을 인정한 기록만 자동 제재에 포함합니다. 첫 회는 경고, 2회부터 3일간 신규 모집·참가·메뉴 매칭 제한입니다.
- 제한 중에도 기존 주문의 송금·수령·환불·신고를 마무리할 수 있습니다.
- 별점 4.8 이상, 완료 거래 5회 이상이면 계정당 1회 최대 1,000원 배달비 쿠폰 조건을 충족합니다.
- 쿠폰은 리더가 그 할인액을 추가 부담하는 데 명시적으로 동의한 모임에서만 사용합니다.
  근처 수령 특별 합의에는 적용하지 않으며, 총 부담액 합계가 실제 배달비와 일치하도록 계산합니다.

## 검증 범위

로컬 PostgreSQL(PGlite, 인증 사용자 모사)에서 마이그레이션 재실행,
기본 주문의 전체 과정과 역할별 권한, 계좌/좌표/신고 접근 제어, 정원,
메뉴 동결, 입금 전 주문 금지, 전원 수령, 주문 후 취소 금지,
근처 수령 합의, 환불, 쿠폰 금액 보존과 중복 사용 방지, 지각 누적·신규 참여 제한을 검사합니다.
이 검사는 실제 은행 송금이나 이메일 배달 성공을 검증하는 것이 아닙니다.
