# 12가지 개선 적용

기존 배프 프로젝트에서 `APPLY-CONSISTENCY-FIXES.sql` 전체를 SQL Editor에 붙여 넣고 실행합니다. 기존 setup, menu-discovery, distance-matching, restore-workflow가 설치된 프로젝트용입니다. 쿠폰·이동포인트·상점 업데이트가 일부 누락되어 있어도 이 파일에 포함되어 있습니다. 새 DB를 만드는 파일은 아닙니다.

파일 전체를 하나의 트랜잭션으로 실행합니다. 중간 오류가 나면 적용도 함께 취소됩니다. 기존 방·참가자·확인된 입금·포인트·상품 가격·교환 기록을 삭제하지 않습니다. 재실행할 수 있으며 기존 상품 가격을 덮어쓰지 않습니다. 예전 개별 SQL로 덮어쓴 경우 마지막에 이 업데이트를 다시 적용해야 합니다.

## 변경 범위

1. 모집에 표시하는 시간과 매칭 시간을 통일합니다. 기존 방 신청은 홈 시간 설정을 참조하지 않습니다. 상대가 수정한 수령 장소·시간을 수정 중인 옛 입력으로 덮어쓰지 못하게 합니다.
2. 시간만 수정할 때 지도 좌표를 보존하고 장소가 바뀌면 기존 좌표를 초기화합니다.
3. 근처 수령 제안에 답하지 않은 상태에서는 주문 확정을 막습니다.
4. 취소된 미확인 송금은 입금 확인 대기로 분리합니다. 리더가 실제 입금을 확인하면 환불액을 확정하고, 참가자는 송금 표시를 실수로 눌렀을 때 본인의 표시를 철회할 수 있습니다. 리더가 상대의 송금 주장을 일방적으로 지울 수 없습니다.
5. 수령 완료와 이동거리 저장을 한 트랜잭션에서 처리합니다. 이미 수령한 요청의 재전송은 거리와 포인트를 다시 기록하지 않습니다. 근처 수령 요청자는 0m입니다.
6. 브라우저 뒤로가기·새로고침을 URL의 화면·방 ID에 연결하고, 검색·목록·모집 초안은 계정별 세션에 보존합니다. 복원 중에는 다른 방 정보가 잠깐 표시되지 않도록 합니다.
7. 가까운 순은 위치 확인 후 선택할 수 있습니다. 공개 수령점 400m 이내/전체 모집을 구분하며, 거리 없는 모집도 전체 목록에서 찾을 수 있습니다.
8. 신청 전에 음식값·예상 배달비·부담액·절약액·거리 요약을 표시합니다. 근처 수령 합의 후에는 실제 분담 규칙을 따릅니다.
9. 로그인 전 모집 안내와 실제 모집 없음·검색 결과 없음 상태를 구분합니다.
10. 완료·취소 방의 기존 accepted 참가자는 채팅을 읽기 전용으로 열람하고, 이전 메시지를 더 불러올 수 있습니다. 탈퇴자의 조회 권한은 기존 정책을 유지합니다.
11. 현재 브라우저의 주문 알림·읽음 상태를 계정별로 보존하고 최신순·모두 읽음을 제공합니다. 메뉴 알림은 기존 DB에 보존됩니다. 기기 간 주문 알림 동기화와 운영체제 푸시는 추가하지 않습니다.
12. 작은 간식 교환권 200P와 교환 목표 진행률을 추가합니다. 기존 적립 규칙·잔액과 상품 가격을 유지합니다.

## 확인 순서

- 리더/참가자 두 계정에서 같은 방을 열고 시간만 변경합니다. 상대 화면 입력이 갱신되는지, 수정 중에는 최신 내용 확인 안내가 나오는지 확인합니다.
- 지도 후보를 저장한 뒤 시간만 저장해 좌표가 유지되는지 확인합니다.
- 근처 수령 제안 대기 중에는 확정이 막히고 합의/취소 후에는 정상 진행되는지 확인합니다.
- 입금 미확인 상태에서 취소한 테스트 건은 입금 확인 대기로 보이고, 실제 송금 여부에 따라 확인/실수 철회 후 환불이 한 번만 처리되는지 확인합니다.
- 수령 화면의 최종 거리와 예상 포인트를 확인한 뒤 수령합니다. 전원 수령 후 적립 기록을 확인합니다.
- 진행 중인 주문이 있는 상태에서 지난 채팅을 열고, 현재 주문 배너는 여전히 진행 중인 방을 여는지 확인합니다.

UI에 프로토타입 경고 문구나 가짜 발급 번호를 추가하지 않습니다. 실제 상품권 발급처 연동은 기존처럼 별도입니다.
