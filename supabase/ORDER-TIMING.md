# 주문 예정과 배달 예상 및 수령 안내

`APPLY-UX-FLOW.sql` 이후 `APPLY-ORDER-TIMING.sql` 전체를 실행합니다. 마지막 확인 결과는 `주문 시간과 수령 기준 변경 완료`입니다. 다시 실행해도 기존 주문·정산·확인 기록을 초기화하지 않습니다.

- `planned_order_at`: 모집 때 정하는 주문 예정 시간입니다. 도착 시각이나 지각 판단에 사용하지 않습니다. 기존 모집의 시간 정보는 이 항목으로 보존합니다.
- `delivery_eta_start`와 `delivery_eta_end`: 리더가 주문 후 배달앱에서 확인해 입력하는 선택 정보입니다. 자동 연동이나 수령 약속이 아닙니다. 리더만 수정할 수 있고 변경 내용을 참가자에게 알립니다.
- 직접 수령은 실제 도착 확인 시각 `arrived_at`, 비대면 수령은 음식 놓기 완료 시각 `pickup_dropped_at`부터 수령 준비 완료로 봅니다.
- 참가자가 수령 가능 안내를 직접 확인한 시각은 `pickup_notice_seen_at`에 한 번 저장합니다. 실제 준비 완료와 이 확인 시각 중 늦은 때부터 10분이 지나야 리더가 지각 확인을 요청할 수 있습니다. 별도 지각 인정 절차와 이용 제한 규칙은 유지합니다.
- 주문 확정 전의 수령 장소는 필요하지만 수령 시각은 필요하지 않습니다. 가상 유저의 행동이 실제 참가자의 수령 안내 확인을 대신하지 않습니다.

모집 취소는 모집 상세, 내 주문 목록, 신청자 관리와 주문 준비/송금 화면에서 찾을 수 있습니다. 주문 전까지만 표시하며, 기존 취소·입금 확인·환불 절차를 그대로 사용합니다.

검사: `node tests/virtual-gps-db.mjs`, `node --test tests/*.test.mjs`, `node node_modules/typescript/bin/tsc --noEmit`, `npm run build`.
