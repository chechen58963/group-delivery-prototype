# 가상 유저와 GPS 이동 기록

Supabase SQL Editor에서 `APPLY-VIRTUAL-USERS-GPS.sql` **전체**를 실행합니다. 마지막 확인 결과는 `가상 유저·GPS 업데이트 적용 완료`입니다. 기존 메뉴·포인트·사용자 피드백 업데이트가 설치되어 있어야 합니다.

## 가상 유저

- 일반 둘러보기 목록에 커피·버거·샌드위치 가상 리더의 방을 표시합니다. 기존 거리·검색·카테고리 필터를 따릅니다.
- 새로 만든 실제 회원의 방에는 6초 간격으로 최대 3명의 가상 유저가 신청합니다. 실제 리더가 수락해야 참가하며, 정원을 초과하지 않습니다.
- 신청자 관리에서 자동 신청을 끌 수 있습니다. 이미 수락한 가상 참가자는 유지합니다.
- 가상 리더는 신청을 수락하고, 실제 참가자가 메뉴를 담으면 주문 준비를 진행합니다. 이 방의 주문 화면은 계좌 송금 대신 주문 진행 버튼을 제공합니다.
- 가상 인물의 메뉴·준비·수령·제안 동의만 자동 처리합니다. 실제 참가자의 동의, 송금, 환불 확인, 수령을 대신하지 않습니다.
- 가상 계정은 `gd_actor_identities`에만 존재합니다. `auth.users`에 가짜 이메일/비밀번호를 넣지 않습니다. 실제 회원의 인증·회원가입·계정 삭제 연결은 유지합니다.
- 업데이트의 기존 RLS와 쓰기 제한은 유지합니다. 가상 인물 생성 함수는 일반 회원이 직접 호출할 수 없습니다.
- 진행은 로그인한 앱이 열려 있는 동안 3초 간격으로 처리합니다. 서버 상주 봇이나 생성형 AI 대화가 아닙니다.

## GPS 이동 기록

- 주문 완료 이후 수령 이동 포인트의 ‘수령하러 출발 · GPS 기록’을 누릅니다.
- 브라우저 위치 권한이 필요합니다. 화면을 벗어나면 중지하고 다시 시작해야 합니다.
- GPS 구간을 합산하되 오차 35m 초과, 오래된 좌표, 빠른 이동, 30초 이상 끊긴 구간은 제외합니다. 정지 상태의 작은 흔들림은 합산하지 않습니다.
- 좌표는 기기 메모리에서 계산하며, 누적 거리만 계정·주문별로 현재 탭에 보관합니다. 이동 경로는 DB에 업로드하지 않습니다.
- 새로고침 후 누적 거리에서 이어갈 수 있지만, 중단 전후 좌표를 연결해서 거리를 더하지 않습니다.
- 수령 확인과 거리 저장은 기존 원자적 처리 안에서 수행합니다. 최대 400m, 내 근처 수령 요청자 0m, 하루 최대 200P 등 기존 규칙을 유지합니다.
- GPS 추정 거리이며 걸음 수 측정이나 부정 적립 방지 시스템은 아닙니다. 실제 기기의 정확도와 권한·화면 전환 동작은 별도 현장 확인이 필요합니다.

## 검사

```powershell
node --test tests/workflow.test.mjs tests/campus.test.mjs tests/live-ui.test.mjs tests/preferences.test.mjs tests/gps-walk.test.mjs
npm install --prefix .tmp-db-check @electric-sql/pglite@0.3.14 --no-package-lock --no-audit --no-fund
node tests/virtual-gps-db.mjs
```

DB 검사는 임시 PostgreSQL에서 기존 마이그레이션과 새 SQL을 실행합니다. 권한, 정상 회원가입, 가상 참가 승인·정원, 가상 리더 진행, 실제 송금/환불 보존, 비대면 수령 동의, 근처 수령 0m, GPS 범위와 중복 적립, 재실행 보존을 검사합니다. 실제 Supabase Auth나 실제 모바일 GPS를 대체하는 검사는 아닙니다.
