# 포인트 상점 적용

기존 프로젝트에서 `APPLY-POINTS-SHOP.sql` 전체를 Supabase SQL Editor에 붙여 넣고 Run 합니다. 기존 이동 적립 테이블, 새 상점, 서버 교환 기능을 순서대로 적용하며 재실행해도 기존 적립과 교환 내역을 보존합니다. 과거 거래의 포인트는 재계산하지 않습니다.

## 적립

- 변경 후 완료되는 거래부터 완료 기본 20P + 등록한 편도 예상거리 5m당 1P입니다.
- 이동거리는 기존과 같이 0~400m이며, 근처 수령 요청자는 0m입니다.
- 거리를 등록하지 않은 참가자도 거래 완료 기본 포인트를 받습니다.
- 모든 참여자가 수령을 확인한 거래에만 지급하고 같은 거래는 중복 지급하지 않습니다.
- 한국 시간 기준 지급일의 적립 한도는 200P입니다. 당일 과거 방식으로 지급한 포인트도 한도에 포함합니다. 포인트를 사용하거나 교환을 취소해도 적립 한도는 초기화되지 않습니다.

## 교환

내 정보 → 나의 포인트 → 포인트 상점에서 상품을 고르고 교환 신청합니다. 서버가 실제 잔액과 상품 가격을 확인해 차감합니다. 같은 요청을 재전송하면 추가 차감하지 않습니다. 발급 대기 신청을 취소하면 차감 포인트를 돌려줍니다. 발급 완료 신청은 사용자가 취소할 수 없습니다.

실제 발급처 API는 연결하지 않았습니다. 교환 신청은 `requested`(화면: 발급 대기) 상태로 저장합니다. 임의의 사용 가능 바코드나 교환권 번호를 생성하지 않습니다. 운영자가 실제 발급된 교환권 번호를 확보한 경우에만 서비스 권한으로 `voucher_code`를 등록하고 `fulfilled`로 변경할 수 있습니다. 브라우저 사용자는 상품 가격·잔액·발급 상태를 직접 수정할 권한이 없습니다.

초기 상품과 포인트 가격은 `points-shop.sql`의 상품 목록에 있습니다. 외부 브랜드 제휴 또는 실제 발급 완료를 의미하지 않습니다. 기존 별점 우수 참가자 쿠폰 정책은 별도로 유지합니다.
